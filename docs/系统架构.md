# 系统架构说明

```text
设备延迟数据 ───────> MRJob / 本地参考实现 ───────> 延迟异常结果
空气质量数据 ───────> Spark RDD + DataFrame ─────> 高风险设备与日期
监测点 + 周边事件 ──> Spark 空间文本联合分析 ────> 周边事件关联结果
                                                      │
                                                      ▼
                                         中文 JSON 报告 + 可视化仪表板
```

## 第一阶段：设备延迟稳定性

系统按照设备和日期聚合延迟记录。MapReduce 的合并器会在数据进入归约器前合并本地的“延迟总和、记录数量”，减少数据传输量。归约器计算每台设备的总体平均延迟，并标记每日平均延迟超过总体平均值指定阈值的日期。

## 第二阶段：空气质量风险

每条有效读数按照以下公式计算综合风险值：

```text
风险值 = CO2 / 1000 + VOC / 300 + PM2.5 / 15
```

RDD 和 DataFrame 两种实现会分别计算设备每日平均风险值，并保留至少有一条读数达到风险阈值的日期。两套实现具有相同的分析语义，可用于对比分布式编程方式。

## 第三阶段：空间文本联合匹配

只有同时满足以下两个条件的监测点和周边事件才会形成关联：

- 欧氏距离不大于设定的空间距离阈值；
- 关键词集合的杰卡德相似度不低于文本相似度阈值。

双重阈值可以减少仅在位置上接近、但内容无关的错误关联。

## 第四阶段：中文报告与可视化

本地参考管线汇总前三个阶段的结果，生成中文 JSON 报告。可视化模块直接使用 Python 标准库生成自包含 HTML 页面和 SVG 预览图，不依赖网络、前端框架或外部图表服务。

HTML 仪表板包括统计卡片、横向条形图、空间文本匹配表和相似度进度条。SVG 预览图会嵌入仓库首页，便于招聘方打开 GitHub 后快速理解项目成果。

## 一致性与可测试性

本地参考实现保持确定性且不依赖分布式运行环境，既可处理小规模数据，也可作为单元测试的可执行规格。MRJob 与 Spark 作业保持相同的计算语义，用于面向大规模数据的分布式执行。
